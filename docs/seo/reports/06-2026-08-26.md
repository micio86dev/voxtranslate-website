**Orphaned content.** Of 35 guides, exactly 15 carry an inbound internal link — three from each of
the five persona pages. The other 20 are reachable only through `sitemap-guides.xml`. There is no
`/guides/` index to link them from, because the route was never created: `src/pages/guides/`
contains only `[slug].astro`.

**The empty registry is the headline.** `/live-translation/for-{platform}/` is a complete route —
template, URL builder, sitemap wiring, an R6 compliance note in its own header — whose `PLATFORMS`
array has been `[]` since task 00. The template body is an `<h1>` and an empty `<slot />`. The
architecture the browser layer needs was designed eight weeks ago and left unfilled.

## 3. What the site publishes that the product does not support

### 3.1 "84 Languages", unqualified — the one that matters

`src/components/home/SocialProof.astro` renders it as a flat stat. `src/pages/llms.txt.ts` opens
with *"voice-to-voice across 84 languages"*. `/{lang}/business/` says transcripts are *"translatable
into 84 languages"*.

Verified against the live catalogue (`GET api.voxtranslate.app/api/languages` and `/api/engines`,
checked 2026-08-26, matching the committed `src/data/engines.json`):

| Tier | Engine | Languages | Rate / min / target language |
|---|---|---|---|
| Standard | Qwen LiveTranslate | **29** | $0.0045 |
| Enhanced | Cartesia | **61** | $0.0666 |
| Premium | Gemini 3.5 Live | **84** | $0.06845 |

84 is the size of the **catalogue** and the reach of **one** tier. `server/src/engine/langmap.rs:9-13`
explains why Standard is 29 and not 60: Qwen reaches 60 targets but only 29 with audio, and *"offering
a text-only language on a speech-to-speech tier hands the user subtitles and silence."* That is
exactly the right instinct, and the homepage undoes it.

This was already known internally. `docs/marketing/directory-listings.md:17-18`: *"Only Premium
covers 84. The homepage headline currently overstates this."* Dated 2026-08-05.

### 3.2 Currency

Everything the server bills is **USD**. `server/src/engine/metadata.rs:53` documents
`cost_per_minute` as USD; `CreditPackage` carries `price_usd` / `credits_usd`
(`server/src/config.rs:1103-1110`). The site is consistent with this since `feature/usd-plan-prices`.
Any external brief quoting a euro per-minute rate is wrong.

## 4. Verified — safe to publish

Each of these was checked against the running product or the server source, not against a doc.

| Claim | Evidence |
|---|---|
| Up to **4 participants**, so up to 4 languages in one call | `MAX_PEERS = 4` `server/src/rooms.rs:16`; every engine's `max_room_size: 4` |
| Billed **per target-language stream**, not per listener. Listening and reading are free | `MeterScope::Speaker { scale_by_target_count }` `server/src/usage.rs:26-46`; `LISTENER_PAYS` off by default `server/src/config.rs:127-129` |
| **Everyone on one language ⇒ nothing billed, and no upstream session is even opened** | `billable_streams()` returns `None` at zero distinct targets and the meter `continue`s (`server/src/usage.rs:69-82,104-137`); `targets.retain(\|l\| l != &ctx.speaker_lang)` leaves the set empty so no session spawns (`server/src/engine/standard.rs:141-147`) |
| Two attendees needing the same language cost **one** stream, not two | same `distinct` count — it deduplicates by language, not by listener |
| Credits, **no subscription required** for calls. $2 free starter credit | balance check, not a plan flag, at `server/src/billing.rs:23-44`; `FREE_CREDITS = 2.0` `server/src/config.rs:1540` |
| Transcripts export as **JSON, PDF, SRT, VTT** | `server/src/api.rs:1292, 1368, 1486, 1497` |
| Webinars bill the **host organisation's** credit pool and require an active org subscription | `server/src/webinar/routes.rs:418-419, 882-890` |
| Webinar attendees get translated subtitles; on the **Enhanced** tier they also hear translated voice | `GET /api/w/{code}/tts-session` `server/src/webinar/routes.rs:2169`; `client/src/scripts/webinar-tts.ts` |
| Extension captures **tab audio only** — never the microphone, never another tab | `chrome.tabCapture` + offscreen document, `src/offscreen/pipeline.ts:158-176`; no mic `getUserMedia` path exists; `PRIVACY.md:15-20` |
| Extension gives subtitles **and** speech, with a 0–100% original-audio control that ducks under the translated voice | `DUCK_FACTOR = 0.25`, `src/offscreen/pipeline.ts:99,495-505`; slider at `src/sidepanel/App.vue:299-314` |
| Extension works on **any tab with sound** — no allowlist, no per-site adapters | no `content_scripts.matches` in `manifest.config.ts:42-98`; no domain string anywhere in `src/` |
| Extension is **Chrome only** | `README.md:124-125` |
| Extension requests no browsing access — `activeTab`, not `<all_urls>` | `manifest.config.ts:35`; justifications in `docs/store/permissions.md` |

**A correction worth making explicitly:** the extension does not work with the Google Meet or Zoom
**desktop applications**. It works with their **web clients**, because it listens to a browser tab.
Every page written in this task says "Web" where that is what is meant.

## 5. Not verified — must not be published

**Latency.** No measured figure exists anywhere in any of the four repositories. This is policy,
stated three times independently: `docs/marketing/directory-listings.md:16` (*"No latency numbers.
None has been measured on the shipped build. Do not add one."*), the extension's
`docs/store/release-checklist.md`, and `server/src/engine/cartesia.rs:44-46` — *"a number in shipped
copy becomes a promise the product has to keep on every network."* `src/data/measurements/` is
empty and `src/lib/measurements.ts` fails the build on a missing or stale file. `/latency/` already
says so in plain language. Nothing in this task changes that.

**"Local recording is free."** No local-recording code path was found. Recordings go to a
Supabase-backed bucket (`server/src/config.rs:1501-1523`), i.e. cloud storage. To publish this, a
local-recording path has to exist and be pointed at.

**Business $49 / Enterprise $199.** `docs/marketing/directory-listings.md:20-22` flags a currency
mismatch between the site and Stripe. The locale files now say `$`, and `feature/usd-plan-prices`
appears to have addressed it, but the Stripe Price objects themselves carry the authoritative
currency and were not reachable from here. **Left untouched.** Someone with Stripe access should
confirm and close the note in that file.

**Stale comment, flagged not fixed.** `server/src/webinar/stt.rs:20` says *"translated TTS audio is
out of scope here — subtitles only."* The Enhanced webinar TTS path shipped after it was written.
The comment misleads anyone reading webinar code; correcting it belongs to a server change, not to
this one.

## 6. Infrastructure findings

**GA4 has never recorded anything in production.** `src/lib/site.ts` reads `GA_ID` from
`PUBLIC_GA_ID`; `.github/workflows/deploy.yml` passes `POCKETBASE_URL` and `PUBLIC_FB_PIXEL_ID` and
**not** `PUBLIC_GA_ID`. Empty ⇒ `gtag.js` never loads ⇒ every `track()` call on the site is a no-op.
The consent architecture around it is correct and is not being changed: `ConsentBanner.astro` loads
trackers only after an explicit accept, and reloads the page on reject to drop anything already
loaded. Needs a GA4 Measurement ID from the owner; the wiring is added regardless so it works the
day one exists.

**No staging.** `deploy.yml` fires only on push to `main`. The staging *mode* is fully implemented
— `functions/_middleware.ts` step 0 short-circuits into Basic Auth + `X-Robots-Tag: noindex`
whenever `STAGING_BASIC_AUTH` is set, deliberately **before** the `*.pages.dev` → apex 301 that
would otherwise make a preview host unreachable. Only the deploy job and the environment variable
are missing.

**`SOCIAL` in `src/lib/site.ts`** holds placeholder X and GitHub handles and is imported by nothing.

**`/contact` 404s** on both the apex and the app host, while `voxtranslate-chrome-extension/PRIVACY.md:113`
and `docs/store/data-disclosure.md` both print it as the support URL. A user following the Web Store
privacy notice hits a dead page.
