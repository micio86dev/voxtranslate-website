is real, and the SEO routes are English-only.

### Defects found and fixed

1. **`src/pages/index.astro` carried a hardcoded canonical to the pre-migration host.**
   The apex root page was telling Google its canonical was `https://website.voxtranslate.app/en/`
   — a URL that now 301s. Every crawl of the site's root hit a canonical pointing at a
   redirect. Now derived from `Astro.site`.
2. **`src/lib/seo.ts` `absoluteUrl()` fell back to the pre-migration host** when `Astro.site`
   was undefined. Now falls back to the apex.
3. **CI only ran on pull requests to `main`.** `develop` is the integration branch, so the
   build, the budget and (now) the schema gate never ran on the PR that would actually
   introduce a regression. Extended to `[main, develop]`.
4. **`CLAUDE.md` and `MEMORY.md` still documented `website.voxtranslate.app` as the canonical
   origin.** Both corrected; the code was already right, only the docs had drifted.

Remaining references to the old host in `functions/_middleware.ts` and `ConsentBanner.astro`
are intentional (legacy redirect source, and the cookie domain allow-list so consent stays
clearable on the old host). Verified absent from every canonical, hreflang and sitemap URL in
the built output.

## 2. Content collections and the schema gate

Schemas live in `src/content/schemas.ts` as plain Zod objects, wired into collections by
`src/content.config.ts`. Splitting them that way is what lets `scripts/verify-schema-gate.ts`
assert against the **same objects the build uses**, rather than a copy that can drift.

Thresholds are exactly as specified in the task: `linguisticNote` ≥ 300, `corridorContext` ≥ 200,
≥ 3 use cases with ≥ 150-char bodies, ≥ 15 glossary terms, ≥ 5 FAQs with ≥ 80-char answers,
4-6 related pairs, ≥ 2 related guides. Comparisons require `verifiedAt`, ≥ 1 primary source URL
and a ≥ 200-char `whenNotToChooseUs`. Guides cap `shortAnswer` at 300.

**Demonstrated, not asserted.** Both failure modes were reproduced against the real build:

```
# a thin pair fixture
BUILD EXIT=1
  linguisticNote: String must contain at least 300 character(s)
  corridorContext: String must contain at least 200 character(s)
  useCases: Array must contain at least 3 element(s)
  glossary: Array must contain at least 15 element(s)
  faq: Array must contain at least 5 element(s)

# a complete, published pair with no measured data
BUILD EXIT=1
  [measurements] "english-to-german.json" does not exist in src/data/measurements/.
  Pair pages may not ship without measured data (AGENTS.md R2).
```

Both fixtures were removed afterwards. `pnpm run verify:schemas` re-proves the guarantee on
every PR — 36 assertions, checking that the schemas **accept** complete entries as well as
reject incomplete ones. A gate that rejects everything would pass a rejection-only test.

The 180-day freshness rule is enforced in `src/lib/measurements.ts` and fails the build, not a
warning. `src/lib/measurements.ts` also declares `measurementSchema` — the contract task 01's
harness must satisfy, matching the output shape in `docs/seo/tasks/01-measurement-harness.md §2`.

## 5. Performance guardrails

`lighthouserc.json` turns R7 into a failing check rather than a note. The existing resource
budget is carried through `budgetsPath`, and the three new rendering routes were added to the
audited URL list. `numberOfRuns: 3` with the median taken — a single pass on a shared GitHub
runner swings several points, and a gate that fails at random gets ignored within a week.

### First CI run: measured, and it changed the configuration

The initial flat rule (SEO ≥ 0.95 everywhere, performance ≥ 0.90 everywhere as errors) failed
on three URLs. Both causes were worth separating rather than papering over.

| URL | Category | Score | Cause |
|---|---|---|---|
| `/latency/` | SEO | 0.93 | Deliberate `noindex` |
| `/languages/` | SEO | 0.93 | Deliberate `noindex` |
| `/en/` | performance | 0.84 (single run) | Pre-existing, unrelated to this branch |

The 0.84 was one noisy sample. Re-run with `numberOfRuns: 3`, `/en/` measured
**0.68, 0.88, 0.88 — median 0.88**. The spread is the finding: a 20-point swing between passes
on the same commit means any single-run gate on this page would have failed at random. The
honest number is 0.88, close to the bar rather than far below it.

**The SEO failures were the assertion's fault, not the pages'.** `/live-translation/` uses the
same `SeoLayout` and the same `BaseLayout` and passed SEO — the only difference between them is
the `noindex` tag, which Lighthouse's SEO category deducts for under "page is blocked from
indexing". That is a controlled comparison, not a guess. Asserting SEO on a page that is
unindexed by design contradicts the design, so the assertion now excludes those two paths — and
returns automatically when they go live, because the pattern excludes them by path rather than
by a named exception.

**`/en/` at 0.88 median performance is a real pre-existing gap.** This branch neither caused it
nor fixes it. `CLAUDE.md` states mobile PageSpeed is 95+, which is plausibly still true of field
data — Lighthouse on a shared CI runner reads consistently lower than PSI — but 0.88 is what the
gate actually sees, and the gap is now visible rather than assumed. Performance is asserted as an
**error on the new SEO routes** (R7's actual wording is "every new page") and as a **warning on
`/en/` and `/en/blog/`**. Blocking an unrelated PR on a pre-existing regression only teaches
people to bypass the gate.

**This is deliberately recorded rather than silently lowered:** someone has to own `/en/`
performance. It is listed in §8.

## 6. Deviations from the task text

1. **Astro 5 loader API instead of the legacy collections API.** The task sketches
   `type: 'data'` at `src/content/config.ts`, which is deprecated in Astro 5. Collections use
   explicit `glob()` loaders at `src/content.config.ts`. The schemas — the actual substance —
   are unchanged.
2. **Sitemaps are hand-rolled, `@astrojs/sitemap` is no longer used.** The integration emits one
   chunked set under a single base name and cannot produce four separately named files, which is
   the whole point of §4. Removed from `astro.config.mjs`.
3. **`@astrojs/sitemap` is still listed in `package.json`.** Removing it needs a regenerated
   lockfile, and `pnpm-lock.yaml` currently pins the single Vite copy that `astro check` depends
   on (see the comment in `astro.config.mjs`). Doing it here would turn a type-check note into a
   hard `--frozen-lockfile` failure. Left as a deliberate, isolated follow-up.
4. **Breadcrumbs omit an intermediate crumb** for `/alternatives/`, `/compare/`, `/pricing/` and
   `/guides/`, because those index pages are not in the URL architecture and do not exist. A
   `BreadcrumbList` item pointing at a 404 is a structured-data error. If deeper breadcrumbs are
   wanted, tasks 02/03 should add real index pages first.
5. **`noindex` emits `noindex, nofollow`**, inherited from `BaseLayout`. For drafts this is
   harmless (they are not publicly linked). `noindex, follow` would be marginally better; changing
   it would also alter the staging path, so it was left alone.

### The failing item

`https://app.voxtranslate.app/` returns `200` with **no `X-Robots-Tag` header**. The call app is
indexable.

This cannot be fixed from this repository. `app.voxtranslate.app` is the Rust application on
Railway, fronted by Cloudflare — the header has to be added either at the Cloudflare edge (a
Transform Rule on that hostname) or in the Axum response middleware in the app repo. The task
notes correctly that an edge header is more reliable than `robots.txt`, which does not prevent
indexing of externally linked URLs.

**Per AGENTS.md §4, this gate does not pass, so task 01 should not start until it is closed.**
